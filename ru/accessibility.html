// Доступность

Создано для всех

GitFocus разработан для вспомогательных технологий. Заявления о доступности перепроверяются для каждого релиза с помощью автоматизированных тестов и контрольного списка на реальном устройстве.

// Возможности

Поддерживаемые функции доступности

🗣️
VoiceOver
Поддерживается

Ключевые маршруты релиза используют описательные метки, атрибуты и логический порядок чтения. Контроль релиза записывает протестированные маршруты и устройство.

🔈
Voice Control
Поддерживается

Интерактивные элементы управления используют доступные имена. Контрольный список на физическом устройстве проверяет критический путь релиза с Voice Control.

🔡
Larger Text
Поддерживается

Текст приложения использует Dynamic Type. Автоматизированное покрытие AX3 и AX5 плюс проверка размера текста 200% человеком требуются перед утверждением этого заявления.

🌑
Темный интерфейс
Поддерживается

Приложение поддерживает светлое и темное оформление. Оба включены в проверки скриншотов и доступности приложения при релизе.

🎨
Differentiate Without Color
Поддерживается

Проверка релиза убеждается, что важные состояния используют метки, формы или иконки наряду с цветом.

◐
Достаточная контрастность
Поддерживается

Автоматические проверки контрастности отмечают возможные проблемы в светлом и темном режимах; рецензент проверяет реальный текст, иконки и фон перед утверждением.

⏸️
Уменьшенное движение
Поддерживается

Контрольный список релиза проверяет, что важное движение учитывает настройку "Уменьшение движения" или имеет статическую альтернативу.

⌨️
Полный доступ с клавиатуры
Поддерживается

Поддерживаемые потоки включают элементы управления, доступные с клавиатуры, и альтернативы для важных действий, выполняемых только жестами.

// Методология

Как мы тестируем

  • 1

    Нативные аудиты iOS — Встроенные от Apple performAccessibilityAudit API checks declared release routes for missing labels, undersized touch targets, and Dynamic Type issues.

  • 2

    Экстремальная отрисовка размера — Каждый экран запускается с размерами текста доступности AX3 и AX5, чтобы проверить, что ничего не падает, не обрезается нечитаемо или не становится недостижимым.

  • 3

    Проверка порядка чтения — Автоматизированные тесты проверяют, что VoiceOver обходит элементы в логическом порядке сверху вниз на ключевых экранах.

  • 4

    Проверка контрастности — Доказательства контрастности WCAG генерируются из семантических регионов, принадлежащих рендереру, затем проверяются на соответствие фактическому светлому и темному оформлению.

  • 5

    Интеграция релиза — Наборы тестов доступности выполняются перед загрузкой скриншотов или метаданных и сохраняют машиночитаемые доказательства.

Стандарты, которым мы следуем

  • Целевые показатели контрастности WCAG 2.1 уровня AA для текста и интерактивных элементов
  • Руководство Apple по интерфейсу для доступности
  • Проверка минимального размера области касания 44pt для интерактивных элементов управления
  • Семантическое покрытие Dynamic Type при размерах текста доступности
  • Совместимые с VoiceOver метки и атрибуты на каждом интерактивном элементе
  • Доступные с клавиатуры альтернативы для всех взаимодействий на основе жестов
