// 접근성

모두를 위한 설계

GitFocus는 보조 기술을 위해 설계되었습니다. 접근성 주장은 각 릴리스마다 자동화된 테스트와 사람에 의한 기기 체크리스트로 재확인됩니다.

// 기능

지원되는 접근성 기능

🗣️
VoiceOver
지원됨

주요 릴리스 경로는 설명적인 레이블, 특성 및 논리적인 읽기 순서를 사용합니다. 릴리스 게이트는 테스트된 경로와 기기를 기록합니다.

🔈
Voice Control
지원됨

대화형 컨트롤은 접근 가능한 이름을 사용합니다. 물리적 기기 체크리스트가 Voice Control을 사용한 중요한 릴리스 여정을 검증합니다.

🔡
더 큰 텍스트
지원됨

앱 텍스트는 Dynamic Type을 사용합니다. 이 주장이 승인되기 전에 자동화된 AX3 및 AX5 적용 범위와 사람에 의한 200% 텍스트 크기 확인이 필요합니다.

🌑
다크 인터페이스
지원됨

앱은 라이트 및 다크 모드를 지원합니다. 둘 다 스크린샷 및 앱 접근성 릴리스 확인에 포함됩니다.

🎨
색상 없이 구분
지원됨

릴리스 검토는 중요한 상태가 색상과 함께 레이블, 모양 또는 아이콘을 사용하는지 확인합니다.

◐
충분한 대비
지원됨

자동화된 대비 확인은 라이트 및 다크 모드에서 후보 실패에 플래그를 지정합니다. 검토자는 승인 전에 실제 텍스트, 아이콘 및 배경을 확인합니다.

⏸️
동작 줄이기
지원됨

릴리스 체크리스트는 중요한 동작이 동작 줄이기 설정을 존중하거나 정적 대안을 갖추고 있는지 확인합니다.

⌨️
전체 키보드 액세스
지원됨

지원되는 흐름에는 키보드 액세스 가능한 컨트롤과 중요한 제스처 전용 작업에 대한 대안이 포함됩니다.

// 방법론

테스트 방법

  • 1

    iOS 네이티브 감사 — Apple 기본 제공 performAccessibilityAudit API checks declared release routes for missing labels, undersized touch targets, and Dynamic Type issues.

  • 2

    극단적 크기 렌더링 — 각 화면은 접근성 텍스트 크기 AX3 및 AX5에서 시작되어 충돌, 읽을 수 없게 잘림 또는 도달 불가능해지지 않는지 확인합니다.

  • 3

    읽기 순서 검증 — 자동화된 테스트는 VoiceOver가 주요 화면에서 논리적인 위에서 아래로의 순서로 요소를 순회하는지 확인합니다.

  • 4

    대비 검증 — WCAG 대비 증거는 렌더러 소유의 의미론적 영역에서 생성된 다음 실제 라이트 및 다크 아트워크와 비교하여 검토됩니다.

  • 5

    릴리스 통합 — 접근성 스위트는 스크린샷 또는 메타데이터 업로드 전에 실행되고 기계 판독 가능한 증거를 유지합니다.

준수하는 표준

  • 텍스트 및 대화형 요소에 대한 WCAG 2.1 레벨 AA 대비 목표
  • 접근성을 위한 Apple Human Interface Guidelines
  • 대화형 컨트롤에 대한 최소 44pt 터치 타겟 확인
  • 접근성 텍스트 크기에서의 의미론적 Dynamic Type 적용 범위
  • 모든 대화형 요소에 대한 VoiceOver 호환 레이블 및 특성
  • 모든 제스처 기반 상호 작용에 대한 키보드 액세스 가능한 대안
